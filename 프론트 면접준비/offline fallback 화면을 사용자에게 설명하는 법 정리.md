# offline fallback 화면을 사용자에게 설명하는 법 정리

## 핵심 요약

- 사용자가 데이터의 최신성을 스스로 판단할 수 있다.
- 캐시된 값을 최신 정보처럼 표시하면 잘못된 의사결정을 유발한다.
- navigator.onLine보다 실제 요청 결과를 상태 판단의 기준으로 삼는다.

## 개념 설명

offline fallback 설명은 현재 화면이 서버의 최신 응답이 아니라 저장된 정보이거나 제한된 대체 화면임을 밝히고 사용자가 다음 행동을 고르게 하는 상태 커뮤니케이션이다.

네트워크 요청 실패와 캐시 적중 여부를 구분해 마지막 저장 시각 `cachedAt`, 사용할 수 없는 기능, `retry` 동작을 화면 가까이에 표시한다.

## 예시

```ts
renderOfflineState({
  title: "오프라인 상태입니다",
  detail: `마지막 저장: ${formatTime(cachedAt)}`,
  unavailable: ["댓글 작성", "결제"],
  action: { label: "다시 연결", command: retry },
});
```

offline 상태에서 cachedAt과 제한된 기능을 함께 보여주고 retry 버튼을 제공한다. 단순히 오류 코드만 노출하지 않는다.

## 면접 답변 예시

> 재연결 행동을 한곳에 제시해 막힌 흐름을 줄인다. 재시도 버튼이 연속 요청을 만들면 불안정한 네트워크에서 부하가 커진다. retry는 중복 클릭을 막고 지연 후 다시 활성화한다.

## 장점

- 오프라인에서도 가능한 읽기 작업을 계속 제공할 수 있다.

## 단점

- 온라인 표시만 믿으면 captive portal 같은 실제 요청 실패를 놓친다.

## 주의사항 / 실무 팁

- 마지막 동기화 시각과 오프라인에서 막힌 기능을 구체적으로 적는다.
