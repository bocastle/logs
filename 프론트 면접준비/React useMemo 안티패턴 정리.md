# React useMemo 안티패턴 정리

## 핵심 요약

- 가벼운 문자열 조합에서 useMemo를 제거하면 의존성 목록과 캐시 수명에 관한 코드가 줄어든다.
- 의존성을 빠뜨린 useMemo는 최신 props 대신 stale 결과를 반환해 단순 재계산보다 찾기 어려운 버그를 만든다.
- 최적화 전후의 render duration과 호출 횟수를 같은 interaction에서 측정해 useMemo의 이득을 수치로 확인한다.

## 개념 설명

`useMemo`는 비싼 계산의 결과 참조를 재사용하는 도구이지 모든 값을 감싸는 성능 보장 장치가 아니다.

의존성 비교와 메모리 보관에도 비용이 있으므로 계산이 가볍거나 참조 안정성이 필요 없으면 오히려 코드만 복잡해진다.

## 예시

```tsx
const visibleItems = useMemo(
  () => items.filter((item) => item.visible),
  [items],
);
```

큰 목록 필터링처럼 실제 비용이 있는 계산에만 적용하고 Profiler로 효과를 확인한다.

## 면접 답변 예시

> 의미적 정확성을 캐시에 의존하지 않으면 React가 값을 버리고 다시 계산해도 화면 동작이 바뀌지 않는다. 부모가 매번 새 객체를 전달하는 상황에서 자식 값만 감싸면 참조 불안정의 실제 원인이 남는다. 참조 안정성이 필요한 소비자가 memoized child인지 effect dependency인지 먼저 밝힌 뒤 가장 가까운 값만 캐시한다.

## 장점

- 실제로 비싼 정렬이나 필터에만 메모를 남기면 성능 최적화 지점을 Profiler 결과와 연결하기 쉽다.

## 단점

- 계산보다 의존성 비교와 결과 보관이 더 비싸면 메모리 사용만 늘고 commit 시간은 줄지 않는다.

## 주의사항 / 실무 팁

- 초기값을 한 번 계산하려는 목적이면 useMemo 대신 useState의 lazy initializer가 생명주기를 더 정확히 표현한다.
