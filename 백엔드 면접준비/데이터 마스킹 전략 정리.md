# 데이터 마스킹 전략 정리

## 핵심 요약

- 민감정보 유출 범위를 줄이면서 필요한 운영 식별자는 남길 수 있다.
- 부분 마스킹 값이 작으면 다른 데이터와 결합해 재식별될 수 있다.
- 필드 allowlist와 데이터 분류표를 API schema에 연결한다.

## 개념 설명

데이터 마스킹 전략은 API, 운영 도구, 로그, 분석 화면에서 PII와 secret이 필요한 수준 이상으로 노출되지 않게 변환하는 보안 정책이다.

필드별 민감도와 사용 목적을 분류한 뒤 redaction, partial masking, tokenization, irreversible hashing을 구분하고 allowlist 기반으로 응답과 로그를 만든다.

## 예시

```text
email: b***@example.com for support UI
phone: [REDACTED] in logs
user_id: tokenization vault lookup for admin export
password_reset_token: irreversible hash only
```

같은 PII라도 고객 응대 화면, 애플리케이션 로그, 외부 반출 파일에서 허용되는 노출 수준이 다르므로 정책을 경계별로 나눠야 한다.

## 면접 답변 예시

> 사고 조사 때 어떤 원문이 저장되지 않는지 빠르게 확인할 수 있다. denylist 방식은 새 PII 필드를 놓치기 쉽다. 샘플 응답, 로그, export 파일을 회귀 테스트에 넣는다.

## 장점

- 권한별 화면과 로그 정책을 일관되게 설명할 수 있다.

## 단점

- tokenization vault 권한이 넓으면 마스킹 우회 경로가 된다.

## 주의사항 / 실무 팁

- 원문 복원이 필요한 값은 vault 접근 권한과 audit log를 분리해 둔다.
