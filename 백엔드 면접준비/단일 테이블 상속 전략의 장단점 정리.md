# 단일 테이블 상속 전략의 장단점 정리

## 핵심 요약

- Single-table inheritance는 여러 subtype을 한 테이블에 저장하고 discriminator로 실제 타입을 구분한다.
- 다형 조회와 공통 ID 관리는 단순하지만 subtype 전용 컬럼이 늘수록 row가 넓고 nullable해진다.
- 타입별 제약, 인덱스와 권한을 discriminator 조건까지 포함해 표현할 수 있는지 판단한다.

## 개념 설명

`SINGLE_TABLE`은 상속 계층의 모든 entity를 하나의 table에 저장하는 ORM 매핑 전략이다. `payment_type` 같은 discriminator가 각 row를 어떤 subtype으로 복원할지 결정한다.

Join 없이 전체 결제 타입을 조회하고 공통 ID와 index를 관리하기 쉽다. 반면 카드 결제에만 필요한 컬럼도 table에 같이 놓여 다른 subtype row에서는 NULL이 된다. 단순 `NOT NULL` 대신 discriminator를 포함한 check constraint와 partial index가 필요할 수 있다.

## 예시

```java
@Inheritance(strategy = InheritanceType.SINGLE_TABLE)
@DiscriminatorColumn(name = "payment_type")
abstract class Payment {}
```

예를 들어 카드 결제 row에만 카드 승인 ID가 필요하다면 `payment_type <> 'CARD' OR approval_id IS NOT NULL` 같은 제약을 별도로 설계한다. Subtype이 계속 늘어날 도메인이라면 table 폭과 migration 빈도를 먼저 예상해야 한다.

## 면접 답변 예시

> Single-table inheritance는 모든 subtype을 한 table에 두고 discriminator로 실제 타입을 구분하는 전략입니다. Join 없이 다형 조회하기 쉽고 공통 ID를 한곳에서 관리할 수 있습니다. 대신 subtype 전용 컬럼이 늘수록 sparse한 넓은 table이 되고 타입별 제약은 discriminator를 포함한 check constraint로 표현해야 합니다. Subtype 수와 조회 패턴, partial index와 권한 분리 비용을 보고 선택하겠습니다.

## 장점

- 상속 타입 전체를 조회할 때 별도 join이 필요하지 않다.
- 공통 식별자와 공통 index를 한 table에서 관리할 수 있다.

## 단점

- Subtype이 늘수록 nullable 컬럼과 row 폭, schema 변경 빈도가 커진다.
- Discriminator 값과 타입별 필드가 어긋나면 잘못된 entity와 데이터가 만들어질 수 있다.

## 주의사항 / 실무 팁

- Discriminator 허용 값과 subtype별 필수 컬럼에 check constraint를 둔다.
- 타입 전용 조회는 discriminator를 조건으로 한 partial index의 효과를 실행 계획으로 확인한다.
